# shipTarget matches the fresh target?

Yes when a readable fresh target equals `shipTarget` and the ship gate
decision `run_snapshot` shows was decided by a person (its decider does
not start with `mode:`): the earlier `proceed` stands, with that
decision's answers (a tree dirty now with no recorded commit or stash
answer is asked at "dirty answer?"). A mode's `proceed` never stands: it
goes back through the MR state read and the gate, so the reach is
declared from the MR as it is now. Unset (`run_field_get` errors), `-`, a
different target or an unreadable store opens the gate, naming both
targets.
