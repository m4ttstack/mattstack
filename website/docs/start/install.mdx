# Install

rt ships inside **mattstack.app**, the mattstack menu bar app. Installing the app installs rt, the daemon, and everything else in the suite.

## Requirements

- An Apple silicon Mac. rt ships an arm64 build only.
- macOS 14 or newer.
- Xcode Command Line Tools. The setup checklist offers to install them.

## Install the app

1. Download the `.dmg` from the [latest release](https://github.com/m4ttstack/mattstack/releases/latest).
2. Drag **mattstack.app** to `/Applications` and open it.
3. The setup window opens and walks you through setup, one step at a time.

### Welcome

A summary of what setup does. Everything it installs is reversible from Settings → Uninstall.

### Full Disk Access

mattstack reads your repos and Chrome's profile, so it asks for Full Disk Access before it does anything else. The page lists three steps:

1. Click **Open Full Disk Access**. System Settings opens at Privacy & Security → Full Disk Access.
2. Turn on mattstack in the list.
3. Click **Reopen mattstack** so the grant takes effect. The app reopens at Your team.

The page shows **Checking Full Disk Access** while it reads the grant, and **Check again** if that check fails. **Continue** unlocks once Full Disk Access is on. Setup that opens again after an update skips this page.

### Your team

Pick one:

- **Create a team**: name it, then paste the URL of an empty repo for it, or let mattstack create a private GitHub repo when the `gh` CLI is signed in.
- **Join a team**: paste the invite code a teammate sent you. The [Join page](#join-your-team) comes next.
- **Just me**: no team repo, no forge account. See [Just me](/start/setup).
- **Restore**: bring back your own setup on a new Mac from your home repo and its age key.

See [Teams and invites](/start/teams) for how teams, invites, and team packs work.

### Join your team

Only a joiner sees this page. It joins the team before the checklist, so the checklist can list everything the team uses.

1. If your forge token cannot reach the team repo yet, the page asks you to connect the team repo's forge first.
2. Click **Join acme**. Joining accepts your invite and copies your team's settings.
3. The page then reads **Waiting for your team admin to approve your request to join the team**. Its three rows show **Invite accepted**, **Team settings copied** with what the team uses, and **Waiting for approval** with how long ago you asked. Your admin gets your request in mattstack and approves it there.
4. When they approve, the page reads **You're in the acme team**. Click **Continue**.

**Continue** unlocks once they approve. The page checks again every 15 seconds, and **Check again** checks now. When mattstack cannot tell whether you were approved, the page shows a warning and reads **Check again, or continue**. **Back** returns to Your team, where you can use another invite.

### The checklist

The checklist of everything setup needs, one page for each group: Your Mac, Accounts, Access, Agents and editors, Browser, Your repos, rt on this Mac, and Team and backup. A group with no rows has no page.

Each page sorts its rows into up to three sections:

- **Needs you**: every step still to do. Each row has its own button, which grants a permission, chooses a folder, connects an account, or shows the steps to take. A row you can finish after Install carries a **Before you finish** badge.
- **You can skip**: the steps you can skip, only if you won't use them. Each row has a **Skip** button.
- **No action needed**: the rows that are ready, the information rows, and the rows Install sets up, which read **Install does this**. It folds to one line that names them. Click the line to open it.

Every step is expected. Three can be skipped: **Skill overrides**, **Chrome sign-in** (shown only when a team pack needs it), and **Mission Control shortcut**. Two are information only and never ask anything of you: **PATH precedence** and **Push access**. Install sets up Login Items, the daemon, the Claude plugins, and your team's packs itself.

**Continue** unlocks once no row on the page holds up Install. A row that only holds up Finish does not hold Continue. The last page's button is **Install**. Click **Re-check** to refresh every row.

**Your Mac** covers macOS, the Command Line Tools, PATH precedence, Login Items, and Notifications. Full Disk Access has its own page before this one, and shows here under No action needed once it is on.

**Accounts** has one row for each integration your team or its packs use. That covers the team's GitHub or GitLab, plus Linear, Slack, StrongDM, and others when the team declares them. **Connect** opens a sheet with a **Create a token on GitLab…** (or GitHub) link to the forge's new-token page. The page opens with the scopes rt requires already checked and the token named `mattstack`:

| Forge | Joining a team | Owning a team |
|---|---|---|
| GitLab | `api` | `api` |
| GitHub (classic token) | `repo`, `read:org` | `repo`, `read:org` |

On GitLab, rt requires only `api`. The link also pre-checks `read_api`, `read_user`, `read_repository`, `write_repository`, and `ai_features`.

Paste the token and Connect. A pasted token missing a scope is refused, naming the scope it lacks; a token already stored that falls short shows as needing you, with the same Connect sheet. A GitLab member needs `api` because the board posts review comments and replies on merge requests as you. The GitHub row is ready without a token when the `gh` CLI is already signed in. The GitLab link targets GitLab 16 or newer.

**Your repos** has one row for each repo your team tracks. Each row is either **Current checkout** (a copy you already have on this Mac; **Locate…** points at it) or **New checkout** (rt clones the repo where you choose; **Choose location…** picks where). A repo rt finds on this Mac starts on Current checkout. A git worktree never counts as a checkout: **Locate…** refuses one and names the main checkout to pick instead. A repo rt can't place shows what to fix on its row. The row for the board's repo also says **The board's review, respond and doctor agents start here**.

A joiner joined the team on the Join page, so their checklist already lists the team's accounts, like Slack and Linear, and the team's repos.

### Installing

Install runs each step and streams its progress:

- links `rt`, `fast-browser`, `gitq`, and `deck` into `~/.local/bin`, puts that folder first on your PATH, and adds the `rtcd` alias to your shell
- registers the rt daemon and deck (which serves the bundled apps) as background services and starts them
- clones the repos set to **New checkout**, with git's clone progress under the running step
- points the board at its repo (**Point the board at widgets**), then restarts it (**Restart the board**), so the board's agents start in that checkout. The board's repo is the first repo in the team's board projects, else the first repo the team tracks
- installs the mattstack Claude Code plugins, turns on your team's pack, and seeds Claude Code's permissions (see [Claude Code setup](#claude-code-setup))
- installs the `rt-context` and `skill-blocks` editor extensions into every VS Code-family editor it finds

### Summary

The last screen checks the checklist again and shows it with a sidebar: **Overview**, then one entry for each group. A **Needs you** entry comes first when a row still needs you.

**Overview** says whether anything is left and shows where things live: the **m** icon in the menu bar, `rt` in a new terminal window, and the board at `board.mattstack`. A step that needs another try is listed there with **Retry from here**. Owners also get **Invite teammates…**.

Above the sidebar, counts such as **12 ready** and **1 skipped** sum up the checklist.

**Needs you** holds every step still to do, apart from the ones you can skip. **Finish** waits on all of them. Some only need to be done before Finish, not before Install, such as **Home repo backup** and **State backup tools**. Two rows gate **Finish** on every Mac:

- **Writing style**: the voice agents use for the reviews, replies, and PR descriptions they post under your name. **Choose style…** offers the mattstack presets or any skill of your own.
- **Fast Browser extension**: Fast Browser drives your real Chrome session through a Chrome extension. Click **Add to Chrome** to open its Chrome Web Store page and add it there. The row then reads **Waiting for Chrome**, with **Open again** to reopen the page, and turns ready when you come back with the extension added. Install already ran Fast Browser's setup, so there is nothing to configure. Only a Mac set to auto connection also pairs. Its row then reads **Loaded in Chrome but not paired yet**, and **Show steps…** walks through the pairing. This row cannot be skipped. Without Chrome installed, this row is skipped.

A step you can skip still holds **Finish** until you do it or click **Skip**.

**Finish** closes the window and starts herdr, the terminal server your agents run in. If herdr cannot start, a notification says why and how to try again.

## After setup

**Setup status…**, just under **Settings…** in the menu bar menu, reopens the checklist at any time, with the same sidebar and no Overview. It opens on **Needs you** when a row needs you, else on **All**, which lists every group. Click a group to see only its rows; click it again, or **All**, to go back. Click a count above the sidebar, such as **1 skipped**, to list those rows from every group. Until setup is finished, **Resume setup…** right below it reopens the wizard at the step you left. On the checklist, it opens the first page that still has a required row, or the last page when none does. Use it to connect an account, rotate a token, or fix a row that slipped. It also warns when a token is close to expiring.

**Settings…** covers the rest: your writing style, startup and updates, team invites, permissions, Fast Browser, and Uninstall. See [The menu bar app](/start/menu-bar-app).

**Home repo backup**: your home repo (`~/.mattstack/user`) keeps your settings versioned on this Mac. Its checklist row offers **Add remote…**: paste the URL of an empty private repo you own, or pick **Create a private repo for me**.

## From a terminal

To set up without the setup window (a VM, CI, or a scripted install), run the same steps from the CLI. mattstack.app still registers the background services and the proxy, so keep it running:

```bash
# run from /Applications, not the DMG
/Applications/mattstack.app/Contents/MacOS/rt --post-install
rt setup status    # the checklist, as text
rt verify          # read-only health report
```

Each checklist button has a CLI equivalent:

```bash
rt setup gitlab connect            # or github, linear, slack, sdm
rt setup repo place github.com/acme/widgets --checkout ~/code/widgets   # or --clone-to <folder>
rt setup repo-root set ~/code      # the folder new clones go in
rt home remote set <url>           # or --create
rt skills writing-style use <id>   # omit the id to pick
rt setup waive tool.mission-control   # skip one of the three steps you can skip
```

Until setup has run, other `rt` commands print a one-line hint pointing at mattstack.app or `rt setup install`.

## Claude Code setup

Install seeds a baseline `permissions.allow` list into every Claude Code config dir. Agents then don't stall on per-tool prompts for calls rt already trusts:

- The mattstack MCP server and the Fast Browser plugin.
- `EnterWorktree`.
- `claude plugin update`.
- The few rt commands skills still run in a shell (`rt gate` and `rt events wait`).

Everything else a skill runs routinely is a tool on the [MCP server](/skills/mcp). Existing entries stay; only missing ones are added. A config dir with no `permissions.defaultMode` gets `auto`, and a mode you already chose stays. A config dir with no `tui` setting gets `"tui": "fullscreen"`, the Claude Code layout rt's pane tools expect. To change it back, remove the `tui` line from that dir's `settings.json`; an update does not put it back.

It installs the `mattstack`, `fast-browser`, and `chat` plugins from the mattstack marketplace, and `superpowers` from `claude-plugins-official`, which the mattstack skills and every team pack call. An existing `superpowers-marketplace` install counts.

## What gets installed

| Component | Description |
|---|---|
| `mattstack.app` | Menu bar app: setup, daemon health, notifications, updates. See [The menu bar app](/start/menu-bar-app) |
| `rt` | Ships inside the app (`Contents/MacOS/rt`), linked at `~/.local/bin/rt` |
| Background daemon | Caches branch and MR data, scans ports, guards git hooks, snapshots the home repo. See [The daemon](/start/daemon) |
| Bundled apps | board, console, chat, and boxscore, served locally through deck |
| `rt-context` extension | Every VS Code-family editor: worktree, branch, and linked ticket in the status bar. See [Editor extensions](/rt/guides/context-extension) |
| `skill-blocks` extension | Every VS Code-family editor: errors, hover, completion and rename while you write skills. See [Editor extensions](/rt/guides/context-extension) |
| Shell integration | `~/.local/bin` first on PATH, plus the `rtcd` alias, for zsh, bash, and fish |
| Bundled helpers | `jq`, `gh`, `glab`, `bun`, `node`, `sops`, `age`, `zstd`, `git-lfs`, `cloudflared`, `fast-browser`, `gitq`, and `deck`, among others, pinned and shipped inside the app |

Helpers resolve by absolute path inside the app bundle. The ones meant to be typed (`rt`, `fast-browser`, `gitq`, `deck`) are linked into `~/.local/bin`.

The checklist's **PATH precedence** row confirms `~/.local/bin` comes first on your PATH through rt's own line in `~/.zshenv`, so your shell finds rt's shims and team intercepts before any conflicting binary. It reads PATH the way a new terminal tab sees it, from a fresh login shell, not from the app. When `~/.local/bin` is missing or not first, the row says so, and offers to add rt's line when that line is not there yet. When the shell does not answer, the row shows an error with **Re-check**.

## Updates

mattstack.app updates itself through Sparkle. **Check for Updates…** in the menu bar menu checks on demand. After an update, the app brings your setup forward on its own with `rt setup update`; see [Updates](/start/menu-bar-app#updates) in the menu bar app guide.
