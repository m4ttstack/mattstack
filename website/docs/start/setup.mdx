# Setup

The first time you open mattstack.app, the setup window asks everything it needs up front, then sets up the Mac in one run. The [install guide](/start/install) covers each screen.

## The order

1. **Three things from macOS**: Full Disk Access, Notifications, and Fancy URLs.
2. **How are you setting up?**: Join a team, Create a team, Just me, or Move from another Mac.
3. **Your invite**: a joiner pastes the invite code and, when the forge needs one, a token.
4. **The wait**: a joiner waits for the team admin to approve. A **You're in** notification says when.
5. **Connect your accounts**: one click each, most in your browser.
6. **This Mac**: where your repos go, and where your settings live: a GitHub repo (rt offers **Sign in to GitHub** when this Mac has no token) or this Mac only.
7. **One progress bar**: nothing needs you until it's done.
8. **This Mac is ready**.

Creating a team skips the invite and the wait. Moving from another Mac goes from your backup repo and recovery key straight to the bar.

If the app quits or relaunches partway, setup picks up where it was by itself. See [When the app quits or relaunches](/start/install#when-the-app-quits-or-relaunches).

## What each answer lets mattstack do

| Answer | What it lets mattstack do |
|---|---|
| Full Disk Access | Reads your repos and Chrome's profile |
| Notifications | Tells you when setup is done |
| Fancy URLs | Serves the apps at addresses like `board.mattstack` |
| Forge token | Reaches the team's repo and opens MRs or PRs |
| Slack | Tracks and posts MRs or PRs in Slack |
| Claude | Runs your agents |
| A team tool's sign-in | Runs your dev servers |
| Linear | Reads and writes Linear tickets |
| Fast Browser | Lets agents drive your real Chrome |
| Your repos | Puts each repo where you want it; the board starts in its repo |
| Your settings | Keeps them on this Mac, or also in a private remote repo you can restore from |

## On a team

Pick **Create a team** to start one, or **Join a team** and paste the invite code a teammate sent you. A joiner waits until the team admin approves, then sees only the accounts and repos their team uses. [Teams and invites](/start/teams) covers roles, invites and how changes travel.

## Just me

**Just me** is the solo setup: rt, the daemon, and Claude Code on this Mac, with rt's integrations (flock among them), no team repo, and no forge account. It's for one person setting up a personal machine rather than joining or starting a team.

Just me skips the invite and the wait, and asks less:

- **Connect your accounts** has GitHub, Claude, and Fast Browser. GitHub ("Optional. Lets mattstack open PRs and MRs") and Fast Browser never hold up **Continue**.
- **This Mac** asks where new clones go instead of listing team repos, and where your settings live: a GitHub repo (rt offers **Sign in to GitHub** when this Mac has no token) or this Mac only.

## What you get

The run ends at a green `rt verify` with no team, no forge token, no `gh` login, and no git remote. The last screen's button is **Open the console**. Board and boxscore, the team-only apps, are installed but off.

## Settings > Apps

**Settings → Apps** lists one row per app with a toggle. A team-only row (board, boxscore) stays toggleable, but carries a note: "Needs a team. Create or join one under Team to use this." Turn one on if you want to look at it anyway.

From a terminal:

```bash
rt apps list              # every app and whether it's on
rt apps enable board      # or disable
```

Deck's own board (`deck.mattstack`) shows an off app as off, with no switch of its own; Settings → Apps is the only place to flip it.

## Upgrading to a team

Nothing about a solo setup is permanent. In **Settings → Team**, pick **Create a team…** or **Join a team…**. Either one reopens the setup window on that path. A joiner waits for approval as usual, and the run then sets up what a team adds: the team itself, a forge token, the team's marketplace, and board and boxscore turning on. Everything already set up (rt, the daemon, Claude Code) stays as it is.

Until you do, `rt team status --json` reports `"mode": "solo"`.

## Connecting a forge account

Solo works without a GitHub or GitLab account, but connecting one adds a few things worth having as a solo developer:

- worktrees auto-dispose once their PR merges
- `rt` can open PRs and MRs directly
- your home repo backup can push to a remote instead of staying local-only

Connect GitHub on the **Connect your accounts** screen, or later with `rt setup github connect`.

## From a terminal

The setup window's Just me flow is two rt commands:

```bash
rt setup intent solo   # record the choice
rt setup apply         # run the install steps solo needs
```

See [Install](/start/install#from-a-terminal) for the rest of the headless flow.
