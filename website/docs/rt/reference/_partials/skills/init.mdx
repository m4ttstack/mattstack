### Starting on a base pack

`--extends <base>` names an org base pack. Init writes `"extends": "<base>"` into the new pack. It leaves out the feature pipeline and any binding the base already sets, so the base's own choices apply. If the org has no base pack by that name, or that base extends another, init stops (`base-missing`) before it writes the pack. It lists the bases the org has. If this team's pack is already written with a different base, or with none, init stops (`extends-conflict`) and names the command that resumes it. When the base's text asks the team for values, init seeds a place for each. A key gets an empty string in `pack/params.jsonc`, and a section gets an empty `pack/sections/<name>.md`. Init then stops (`params-missing`) with the list and the base file that asks for each. Fill them in and run the same command again. Init resumes, leaves the files as they are, and carries on through compile, check, install and publish. See [Team values in shared fills](/skills/packs#team-values-in-shared-fills).
