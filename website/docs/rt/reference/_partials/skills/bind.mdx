Without `--pipeline`, the fill becomes the default for every pipeline, under the fragment's top-level `bindings`:

```bash
rt skills bind stage-evidence domain acme:capture-evidence --pack acme
```

A stage takes its bare name (`stage-evidence`) or the plugin-prefixed name the fragment stores it under (`mattstack:stage-evidence`). Both bind the same slot, and the output names the bare stage. Bind refuses a prefix that is not the stage's own plugin. A roster verb (`work`, `ship`) takes no prefix.

With `--pipeline`, the fill overrides that slot for one pipeline only. Every other slot, and every other pipeline, keeps the default:

```bash
rt skills bind stage-evidence domain acme:capture-a11y-evidence --pipeline accessibility --pack acme
```

The override lands in the fragment under `pipelines.accessibility.bindings`. When the pipeline is still a plain stage list, bind turns it into the object form first:

```jsonc
"pipelines": {
  "accessibility": {
    "stages": ["mattstack:stage-provision", "...", "mattstack:stage-watch-ci"],
    "bindings": {
      "mattstack:stage-evidence": { "domain": "acme:capture-a11y-evidence" }
    }
  }
}
```

A slot set to `""` under `pipelines.<name>.bindings` in the fragment unbinds that slot for that pipeline only. Bind itself refuses an empty fill, so write that value in the fragment by hand.

Bind refuses `--pipeline` when:

- the pack's bindings file does not declare the pipeline (`pipeline "<name>" is not declared in this pack's manifest`): declare it in `pack/skills.jsonc`, then run `rt skills materialize`,
- the pipeline's name does not match `[a-z][a-z0-9-]*`,
- the pipeline's name contains `--` (`pipeline "<name>" must not contain "--"`),
- the pipeline's stage list does not carry the stage,
- the verb is a compiled stage copy (`stage-evidence--accessibility`): name the stage and pass `--pipeline` instead.

## Remove a pipeline's override

`--unset` removes the override this pack's fragment sets for one pipeline, so the slot reads the default fill again. Name the pipeline with `--pipeline` and pass no fill:

```bash
rt skills bind stage-evidence domain --pipeline accessibility --unset --pack acme
```

Bind then recompiles the pack. Once the stage's fills for that pipeline match the default again, the recompile removes the `stage-evidence--accessibility` copy. This holds even when the pipeline keeps overrides on other stages. A pipeline left with no overrides goes back to a plain stage list in the fragment; one that keeps others keeps its object form.

The result reads `to` as the fill the slot has afterwards, and `--json` adds `"unset": true`. If a lower layer, such as a base pack the pack extends, still overrides the slot, the output says that layer's override still applies. `--dry-run` shows the default fill as `to` even then, because it cannot see the layer underneath.

Bind refuses `--unset` when:

- `--pipeline` is missing (`--unset removes a pipeline override; name the pipeline with --pipeline`),
- a fill is given (`--unset takes no fill`),
- the pipeline has no override for that slot (`<pipeline> has no override for <verb>.<slot>`),
- the override comes from another layer, such as a user override (`<pipeline>'s override for <verb>.<slot> comes from <layer>; remove it there`).

An unset removes the override. Writing `""` under `pipelines.<name>.bindings` by hand does something different: it keeps the override and leaves the slot unbound for that pipeline.
