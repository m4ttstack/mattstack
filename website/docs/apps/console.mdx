# console

## What it is

console is the management console for mattstack: a local web app that shows what is running, what needs you and what a run actually did. It reads run state, wiring and settings through the same client the `rt` CLI and daemon use, so it has no separate database and no write path the CLI does not already have.

## Open it

Open console from the mattstack window. Turn it on or off with [`rt apps`](/rt/reference/apps). It is most useful once rt is set up on your Mac, because without it the board and settings pages start out empty.

## What you do in it

**Watch your runs.** The Runs page shows every pipeline run on this Mac: what waits on you, what is live and what ran earlier, grouped by day. Filter it by state, or pick a repo in the top bar. The repo list holds the repos rt has registered. It updates as runs change, with no refreshing.

**See a day's runs.** Switch the Runs page to Timeline to see one day's runs as bars across the working day, 8 AM to 6 PM. Switch to Night for the hours from 6 PM to 8 AM. Time a run sat idle or held is not drawn. A calendar beside the bars shades each day by how many runs moved on it; pick a day to open it. Under the calendar, the day's time splits into stage work, waiting on CI and waiting on you. Below that are the decisions you made.

**Follow a live run.** Open a live run for what it is doing now and its story so far. The header card holds the run's MR and branch. The story lists the run's stages beside the one you pick. Each answered decision reads as its record inside its stage: a review's verdict and findings, a reply's threads, or the form with the picks checked. When the run asks you a decision, answer it right on the page, one question at a time. A review or respond run points you to the board for its decisions instead.

**Resume a run whose pane is gone.** When a live run has no pane left, its header's menu offers **Resume**, which picks up the run's Claude session in a new pane.

**See what a run did.** A finished run opens as a record. Its header shows how it ended, with its MR and branch. Its tabs hold its story, its evidence when a work run captured some, and the inputs it ran on. Each decision sits in the story, inside its stage. Search finds a run across every run.

**Read the wiring.** The wiring map shows the skill and pipeline graph, its surfaces, its health and its version history. When there is more than one pack, pick the one it reads from the team menu in the top bar.

**Browse and change settings.** The settings explorer lists every registered key across the default, org, team, user and machine scopes, and shows where each value is set. Each section sorts its keys by the scope whose layer sets the value, or by the key's first scope while nothing sets it. Filter by name or by scope; while any setting is broken, a chip counts them and filters to them. A per-project setting picks its project inside its row, starting on the first project that sets it. A single value saves as soon as you commit it: flip a toggle, pick an option, or press Enter or leave the field. A structured value opens as a draft in a JSON editor, with a form one click away, and saves when you press Save. The JSON editor completes and explains each field from its setting's schema. console has no config file of its own, so this is the place to edit settings in the app.

**Look at another team's settings.** On the settings page, the top bar names your org and team. On every page, its right end shows your name and role. An org admin can open any team from the team menu in the top bar, and a team owner the teams they own; a member sees only their own team. While you look at another team, the page lists only its org and team settings, since your user and machine settings are not that team's. A change you make there saves to that team's shared settings. **Back to** your team returns you.

## Settings that matter

console has no keys of its own. What it shows and edits are the shared settings every mattstack app reads; see [Settings](/start/settings).
