# rt skills compile

`rt skills compile` turns engine sources (mattstack block trees: a folder holding `index.block.md` typed `pipeline-step`) plus a manifest's bindings into committed `SKILL.md` files under a pack's `skills/` (surface-public) and `attachments/` (internal) directories. `commands/skills.ts` resolves the pack, roster, manifest and targets; `compileBlockSkill` in `compile-blocks.ts` resolves every block's props, renders the tree (`blocks/render.ts`) and lints the result with `compile.ts`; `placeholders.ts` renders the `{{...}}` markers.

## Where `${CLAUDE_SKILL_DIR}` points

Claude sets `${CLAUDE_SKILL_DIR}` to the directory of the skill it *invoked*. Only surface-public roster verbs are invoked by name, so only their compiled bodies may use the token as their own directory. Every other target is read as a file by a public skill, so the compiler rewrites its `${CLAUDE_SKILL_DIR}/...` references to the directory a pack-side reader reaches it at:

| Target | Host dir the body is rewritten to |
| --- | --- |
| public roster verb | `${CLAUDE_SKILL_DIR}` (unchanged) |
| stage listed public in `surface.jsonc` | `${CLAUDE_SKILL_DIR}/../../skills/<name>` |
| stage not listed public | `${CLAUDE_SKILL_DIR}/../../attachments/<name>` |
| internal roster verb | `${CLAUDE_SKILL_DIR}/../../attachments/<name>` |

Fills and includes vendored into such a target land under `<host dir>/parts/<prop parts dir or include-name>/` (a root prop's dir is `<prop>`, another block's `<block path>/<prop>`, an included tree's `+<block id>/<prop>`), and their own `${CLAUDE_SKILL_DIR}` references are rewritten to that parts dir. `{{stage.dir}}` renders the host dir inside any attachments-side target and is an error in a public verb. The host dirs of every stage and every internal roster verb are exempt from the emitted-file lint, so a target that vendors a fill or include lints clean.

Known limit: the `../../` hop assumes the reader's own skill lives at `<pack>/skills/<reader>`. A reader outside the pack (another plugin's skill) resolves `${CLAUDE_SKILL_DIR}/../../...` against its own plugin, so pack text meant to be read from outside must name files relative to itself instead.

## `{{verb.path:<name>}}`

Renders the path from the current output file's directory to `<name>`'s compiled `SKILL.md`: `../<name>/SKILL.md` when both targets sit on the same side, `../../skills/<name>/SKILL.md` or `../../attachments/<name>/SKILL.md` across sides. It is a reading path, relative to the file that carries it, never a shell path. `<name>` must match `[a-z][a-z0-9-]*` and be a compiled target of this pack (roster verb or stage); a `--verb` or `--preview` compile still resolves paths to targets it is not emitting, and its lint may then report them as not emitted. Allowed in engine bodies and in fills.

## `{{pack.path:<attachment>/<file>}}`

In a compiled target (its engine text or an inlined fill), renders `<skill dir>/references/<attachment>/<file>`, where `<skill dir>` is `${CLAUDE_SKILL_DIR}` for a public verb and the host dir otherwise, and `references.ts` copies the whole unit (`<side>/<unit>/`, or the planned base folder for an emitted base attachment) into the target's `references/<unit>/`. Each target gets its own copy; a unit is copied once per target. A copied `.md` file's own `${CLAUDE_SKILL_DIR}` is rewritten to its copy's folder (`<skill dir>/references/<unit>`), the way an inlined fill's points at its parts dir, so a sibling it names resolves inside the copy. It is read as a plain file, so it renders through `substituteAttachmentPlaceholders` like an emitted base attachment: team markers (only in a unit from the org base), `{{pack.name}}`, `{{verb.path}}` relative to the copy, plus a flat `{{include}}` and a `{{pack.path}}` that copies its unit into the same `references/`. A placeholder whose value depends on the reading skill (`stage.dir`, `stage.fields`, `pipeline.stages`, `pipeline.table`, `run-list.pipelines`, `work-type`, `run-start.flags`, `compiled-from`) or an include it cannot resolve throws; every other brace passes through as text. Other files are copied as written. The target's whole output dir is rewritten on every compile, so a stale copy goes with it.

`<attachment>` must be an existing directory under exactly one of the pack's `attachments/` or `skills/` (that picks `<side>`; both is an error), must not name a compiled target (its output exists only after a compile), and `<pack>/<side>/<attachment>/<file>` must exist when the compile runs; `<file>` is one or more segments with no `..`. Rendered paths are exempt from the emitted-file lint. A fill's `${CLAUDE_SKILL_DIR}` rewrite runs before substitution, so a rendered path is never rewritten to a parts dir. In an emitted base attachment (`substituteAttachmentPlaceholders`), it still renders the source path `${CLAUDE_SKILL_DIR}/../../<side>/<attachment>/<file>`, anchored on the invoking skill's dir.

## `{{team.<key>}}` and `{{team.section:<name>}}`

Org base text carries values each team pack supplies; the user contract is the "Team values in shared fills" section of `website/docs/skills/packs.mdx`. `team-params.ts` owns the pass: `readTeamValues` reads the team pack's `pack/params.jsonc` and `pack/sections/*.md`, and `resolveTeamMarkers` resolves one body against a `TeamContext`, recording each missing required marker instead of throwing so the whole pack's gaps refuse once.

- **Base fills.** `resolveFillTeamMarkers` (`placeholders.ts`) runs on a fill's body before any other substitution, so a value is never read as an include. A section or a value may carry `{{pack.path:<a>/<f>}}` and `{{verb.path:<verb>}}` and no other `{{`; the host text's own pass resolves them after the splice, so they render the way its own placeholders do. Their hand-typed paths are checked where they are written (`teamInputPathDiagnostics`, run by `commands/skills.ts` for compile and check and by the language server), never from the host after the splice. A value can still hold `${CLAUDE_SKILL_DIR}`, which the rewrite after it turns into the fill's parts dir like any other text in the body. It resolves only when the fill's plugin is an org base (`TeamContext.basePlugins`); a marker in any other fill, anywhere in an inlined fill's frontmatter (`loadAttachment` keeps the first one, since the body it hands on has none), in any bound fill's `allowed-tools` (a fill bound by reference keeps the rest of its own frontmatter), or in a pack with no plugin name (no `TeamContext`) throws. So does a marker in a file a base fill vendors (`compile.ts`), which is copied as written.
- **Copied attachments.** `substituteAttachmentPlaceholders` resolves a copied `.md` file's body first; a marker in its frontmatter throws, and `assertNoTeamMarkerInRawFile` throws on one in a copied non-`.md` file.
- **One line.** A marker sits on one line: `{{` then a line break then `team.` throws with the line of the braces. An indented `{{team.section:<name>}}` indents every non-blank line of the section by the same amount; its seam stays at column 0, where every seam parser looks for it.
- **Required.** Only markers in text this compile emits count, so a `--verb` compile checks only that verb. `commands/skills.ts` collects the gaps (`missingOf`) and refuses with `missingValuesFailure` before writing anything; check, preview, anatomy and composition refuse with the same list.
- **Seams.** An inserted section inside an inlined fill gets its own five-token seam, `<!-- part: section:<name> source=<team pack>:pack/sections/<name>.md version=<team pack version> path=pack/sections/<name>.md lines=1-<n> -->`, so `drift.ts` and the anatomy and console views keep counting lines; drift on it reports the cause `team`. An absent optional section drops its line, so the prop seam around it counts one source line fewer (`spanOf` in `placeholders.ts`), or the walkers would run that value into the part after it. Copied attachments carry no seams.
- **Floor.** When any emitted base text used a marker, compile writes `pack/requires.json` `minEngine` no lower than `TEAM_MARKERS_MIN_ENGINE`.
