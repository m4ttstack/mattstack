# mattstack docs: docs.mattstack.dev

Date: 2026-10-06
Status: design approved in conversation, awaiting spec review
Base: PR #667 (`org-teams-1-resolver`), which rewrites the teams guide, the
team reference pages and the README. This work rebases onto that branch as it
moves and lands after it.

## Goal

rt.cool predates mattstack and documents rt alone. The suite now ships as
mattstack.app with served apps, gitq, packs and plugins, and the docs, the
README and the release skills should describe that suite.

Four outcomes:

1. The Docusaurus site in `website/` becomes the mattstack docs, served at
   `docs.mattstack.dev`, with rt as one section of it.
2. The site takes the mattstack.dev landing page's look: its tokens, type and
   nav.
3. The repo README describes the monorepo as it is today.
4. The release skills and scripts check and deploy the whole site, not only
   rt's command reference.

## Non-goals

- No change to how rt's command reference is generated, or to the rule that
  generated pages are never hand-edited.
- No deep per-app task guides. Each app gets one overview page this pass.
- No move of the mattstack.dev landing page into this repo.
- No search provider (Algolia or a local search plugin). That is a follow-up.

## 1. Site architecture and URLs

One Docusaurus project stays at `website/`. Its package is renamed
`rt-docs` to `mattstack-docs`, `url` becomes `https://docs.mattstack.dev`, and
`baseUrl` stays `/`.

One docs plugin carries five sidebars, each opened by a navbar tab (`type:
"docSidebar"`):

| Tab | Folder | URLs |
|---|---|---|
| Get started | `website/docs/start/` | `/` and `/start/...` |
| Apps | `website/docs/apps/` | `/apps/<app>` |
| rt CLI | `website/docs/rt/` | `/rt/guides/<name>`, `/rt/reference/<path>` |
| gitq | `website/docs/gitq/` | `/gitq/...` |
| Skills | `website/docs/skills/` | `/skills/...` |

`sidebars.ts` defines the five sidebars, each autogenerated from its folder.

**rt's generated reference** moves from `website/docs/reference/` to
`website/docs/rt/reference/`. `scripts/gen-docs.ts`, `scripts/check-docs.ts`,
`scripts/lib/docs-hand.ts` and `scripts/lib/docs-clean.ts` take the new root.
The hand-written allowlist (`_partials`, `_category_.json`, `global.mdx`)
moves with it, so regeneration still never removes a hand-written file. The
generated cross-links and the `_partials` import path
(`@site/docs/rt/reference/_partials/...`) follow. The turbo `docs:check`
inputs in `turbo.json` follow.

**gitq is folded in.** `apps/gitq/website/docs/*` moves to
`website/docs/gitq/`. `apps/gitq/website/` is deleted: its config for a GitHub
Pages site that was never deployed (Pages is 404 on the repo), `serve.ts`, its
lockfile and its CSS. The shared site adds `@docusaurus/theme-mermaid` and
`markdown.mermaid: true`, which gitq's pages use. gitq's
`tests/docs-coverage.test.ts` reads `website/docs/gitq/reference/` from the
monorepo root. `apps/gitq/.gitignore` drops its `website/` lines.

**Hosting.** A new Cloudflare Pages project, `mattstack-docs`, with
`docs.mattstack.dev` as its custom domain, since Pages projects cannot be
renamed. `scripts/deploy-docs.sh` deploys `website/build` to it.
`mattstack.dev` is already a zone on Matt's Cloudflare account, so the
subdomain is one custom-domain add in the Pages dashboard.

**rt.cool redirects.** The `rt-cool` project gets a redirect-only deployment:
a `_redirects` file under `website/redirects/rt-cool/` and a
`scripts/deploy-rt-cool-redirects.sh` that deploys only that folder. Rules,
all 301, in this order:

```
/reference/*         https://docs.mattstack.dev/rt/reference/:splat
/guides/<rt guide>   https://docs.mattstack.dev/rt/guides/<rt guide>
/guides/<moved>      https://docs.mattstack.dev/<new home>
/getting-started/*   https://docs.mattstack.dev/start/:splat
/*                   https://docs.mattstack.dev/
```

The guide rows are one line per guide, since guides split between the rt tab,
Get started and Skills (section 3). The getting-started rows are explicit
where a page is renamed.

**Outside links.**

- `rt-tray/Sources-core/Window/DocsSite.swift` and its check in
  `AppMenuChecks.swift` move to `https://docs.mattstack.dev/`. It ships with
  the next release.
- The mattstack.dev landing page's "Docs" nav link becomes
  `https://docs.mattstack.dev`, as one commit in that repo, deployed with its
  `deploy.sh`.

## 2. Look and feel

The landing page's tokens are copied exactly, not approximated.

- **Tokens.** `website/src/css/tokens.css` holds the landing `:root` palette
  (`--bg #0e0e14`, `--bg-alt`, `--surface`, `--border`, `--border-soft`,
  `--fg`, `--muted`, `--dim`, accent `#e64980`, `--accent-wash`,
  `--accent-line`, `--nav-bg`) and its light set. `custom.css` maps Infima onto
  them: the primary colour scale from `#e64980`, background, surface, navbar,
  sidebar, code, admonitions and table borders. Light and dark map from
  Docusaurus's `[data-theme]` attribute.
- **Colour mode.** `respectPrefersColorScheme: true` with the default taken
  from the system, as the landing page does. The toggle stays.
- **Type.** Inter 400 to 700 from Google Fonts (the landing page's own link),
  with the landing's negative letter-spacing on headings. Code uses the system
  monospace stack.
- **Navbar.** It matches the landing nav: sticky, `--nav-bg` with the
  saturate-and-blur backdrop, a `--border-soft` bottom rule, and the app icon
  with "matt" plus an accent "stack". Muted 13.5px links go to `--fg` on hover.
  The five tabs sit on the left. GitHub, Releases and a pink Download pill
  (the landing's `.nav-dl`) sit on the right. The two-colour brand needs one
  swizzle, `NavbarLogo` (wrap), and it is the only swizzle.
- **Details.** The active sidebar item takes `--accent-wash` with an
  `--accent-line` edge. Code blocks sit on `--surface` with `--border`. The
  footer carries one row of links back to mattstack.dev, GitHub and Releases.
  The Prism themes are picked by eye against both backgrounds.
- **Assets.** `mattstack.dev/assets/app-icon.png` is copied into
  `website/static/img/` and used as the favicon and the navbar logo.
  `favicon.svg` is removed.

**Design first.** Before any CSS, the docs shell is drawn in pen.dev next to
the landing design (`mattstack.dev/docs/design/`): the navbar, the sidebar, a
guide page and a reference page, each in both schemes. Matt signs off on that
board.

**Verification.** Fast Browser screenshots of the built site in both schemes,
side by side with the landing page and the board. Anything that reads wrong is
named plainly, not just reported as passing contrast maths.

## 4. README

Written with the github-readme skill, on top of #667's README.

- **Opening:** one paragraph on what mattstack is, a screenshot, and links to
  docs.mattstack.dev and mattstack.dev.
- **What's inside:** a table, one row per piece with its docs link and its
  folder:
  - the app (`rt-tray/`)
  - rt (repo root)
  - the served apps (`apps/board`, `deck`, `console`, `chat`, `boxscore`)
  - gitq (`apps/gitq`)
  - the packages people use (glance, rt-client)
  - the plugins (`plugins/mattstack`, `herdr-chat`)
  - fast-browser and flock, from their own repos
- **Install:** download the DMG and run setup, plus the requirements line from
  the install guide.
- **Repo layout:** root, `apps/`, `packages/`, `plugins/`, `rt-tray/`, `ui/`
  and `website/`, one line each.
- **Development:** `bun install`, `bun run check`, `bun run test` and the
  per-app scripts, pointing at `docs/development.md`, `apps/AGENTS.md` and
  `docs/release-and-distribution.md`.
- **Contributing and License:** kept.
- **Dropped:** the rt feature tour, everyday commands, configuration and
  plugins sections, which already live in the rt CLI tab.

Side fixes: the rt.cool links in `packages/rt-client/README.md` and
`package.json` (`homepage`), `apps/gitq/README.md`'s paragraph on its
`website/` folder, and gitq's `configuration.mdx`.

## 5. Release and docs conformance

**rt:docs** (`skills/rt-docs/SKILL.md`) keeps its id and is rewritten for the
mattstack docs: docs.mattstack.dev, the five tabs, the new reference root and
URL facts, and a first node that reads the impact list.

**Docs impact list.** `scripts/lib/docs-impact.ts` is new, pure and
unit-tested. It maps a list of changed paths to the docs areas to review:

| Changed path | Review |
|---|---|
| `commands/`, `lib/command-tree-def.ts` | rt CLI tab (reference regenerates; guides by judgment) |
| `apps/<app>/` | `docs/apps/<app>.mdx` |
| `apps/gitq/` | gitq tab |
| `plugins/` | Skills tab |
| `rt-tray/`, `lib/setup/`, `lib/team/`, the settings registry | Get started |

A path matching no row adds nothing. `scripts/update-docs.ts` prints the list
for `<base>..HEAD`, and rt:docs reviews those pages before anything else.

**update-docs.ts** takes the new reference root, says docs.mattstack.dev in its
agent prompt, and stages `website/docs/rt/reference` with the notes.

**Fast path.** `rt release apps` already admits `website/` but runs no docs
step, so an app-only release never touches its app's page. `fast-path.md`
gains an rt:docs pass scoped by the impact list to the apps that moved, before
the verb runs. Whether those pages commit with the verb's notes commit or in a
commit ahead of it is settled in planning against `lib/release`, with no
change to the verb's gate.

**Publish and finish.**

- `scripts/deploy-docs.sh` deploys to `mattstack-docs`.
- The `rt.cool setup missing` and `rt.cool deploy failing` gates become
  `docs site setup missing` and `docs site deploy failing`, with the same
  takes, rounds and budget.
- A new smoke step runs after the deploy. It checks for 200 from the docs home,
  one rt reference page and one gitq page, and for a 301 from
  `rt.cool/reference/cd` to `docs.mattstack.dev/rt/reference/cd`. A failure
  enters `docs site deploy failing`.
- `rt-release/SKILL.md`'s "stopped before rt.cool" resume wording and
  `mattstack-release/SKILL.md`'s division-of-duties line move to "the docs
  site".

**CI.**

- A path-filtered job builds the site (`bun install --frozen-lockfile && bun
  run build` in `website/`) when `website/**`, `scripts/gen-docs.ts`,
  `scripts/lib/docs-*.ts`, `lib/command-tree-def.ts` or `apps/gitq/**` change.
  The `throw` link settings only protect a site that something builds.
- `lib/__tests__/no-rt-cool-links.test.ts` fails on any `rt.cool` in tracked
  files outside `website/redirects/`, the rt-cool redirect script, this spec,
  `RELEASE_NOTES.md` and dated docs under `docs/superpowers/`.
- gitq's `docs-coverage.test.ts` is kept, reading the new folder.

**Process.** Every skill edit goes through superpowers:writing-skills (RED
baseline, then GREEN). AGENTS.md's pointers to `website/` and rt.cool are
updated, and so is the agent memory note on the rt.cool site.

## Order of work

Each step is a separate PR off this branch's base, so each can be reviewed on
its own:

1. Hosting and structure: the move to five folders, the generator root, the
   gitq fold-in, the config, the CI build job and the redirect file. The site
   builds green with today's content in its new places.
2. Look and feel: the pen.dev board, Matt's sign-off, then the theme, and
   screenshots of both schemes.
3. Content: Get started, Apps, Skills and the rt intro trim.
4. README and side fixes.
5. Release conformance: docs-impact, update-docs, the skills, the smoke step
   and the no-rt-cool guard.
6. Cutover, done by Matt with me: create the `mattstack-docs` project, add the
   docs.mattstack.dev domain, deploy, deploy the rt.cool redirects, and
   repoint the landing nav and the tray.

Step 6 is where anything goes public, and it happens only on Matt's go.

## Risks

- **#667 keeps moving.** It was updated during this design. Rebase before each
  PR, and expect the teams guide and pack pages to need a second look after
  each of its pushes.
- **Bookmarked rt.cool deep links.** The redirect rules are only as complete as
  the guide table. The smoke check covers one reference URL. Before cutover,
  check every path in the old build's `sitemap.xml` against the redirects.
- **Generator root move.** A wrong root makes `docs-clean` delete hand-written
  files. A test asserts that `_partials`, `_category_.json` and `global.mdx`
  survive a regeneration at the new root.
