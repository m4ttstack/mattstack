# Generic doctor stack-parent check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The generic board doctor proves an MR has no open stack children with a live `mr_list` read before its server-side rebase, and tests pin that read on GitHub.

**Architecture:** Two new nodes in the doctor's Diagnose and rebase graph (`apps/board/skills-src/doctor/diagnose.md`) sit between the fix-class license and the lease check; any listed child, or a read that cannot prove none, ends the run in `error`. The tool and daemon already answer on both forges; two tests pin the GitHub half at `mr_list` and at `mr:list-live`.

**Tech Stack:** Board skill sources (Markdown with dot graphs), `bun run skills:expand:board`, `check-dot.py`, `plugins/mattstack/tests/certify.sh`, `bun:test`.

**Spec:** `docs/superpowers/specs/2026-11-12-doctor-stack-parent-check-design.md`

## Global Constraints

- No live forge call of any kind. RED and GREEN agents describe calls against a stated fixture and execute none.
- No em or en dashes in anything written (skill text, tests, commits, PR body). Check with `rg -n '\x{2013}|\x{2014}' <files>`; exit 1 means clean.
- rt runs from source only under an isolated HOME: `T=$(mktemp -d); env -i HOME=$T PATH=$PATH TMPDIR=${TMPDIR:-/tmp} bun run <script>`; `rm -rf "$T"` after.
- Edit board skills only in `apps/board/skills-src/`; `apps/board/skills/` is regenerated by `bun run skills:expand:board` and committed with the source edit.
- Lane fence (agreed with skills-watch-ci): in `diagnose.md`, only the node declarations and edges between `Server-side rebase licensed?` and `Lease mode (before the rebase)?`, plus one new prose bullet placed between the "What is broken" and "A pipeline with no verdict" bullets (so one untouched bullet separates this hunk from that lane's "The rebase poll" edit). In `SKILL.md`, only the `clean-api-rebase` entry under "Fix classes". Never touch `entry.md`, `mr_rebase {mrUrl}` or anything downstream of it.
- Nothing under `plugins/mattstack/` changes, so no plugin version bump. No edit to any team pack or fill.
- No ticket ids in skill text (certify's `no-ticket-ids` check).
- Board graphs keep sentence ids: run `check-dot.py` without `--short-ids`.
- `bun test <file>` from the worktree root, only on the test files this plan touches. Stage named files only.
- Commit messages are imperative and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A child MR that is a draft, by another author: it counts as a child and ends the run (Task 3 GREEN `stack-parent`, whose child `!42` is a draft by `bob`).
2. An empty list that says `full: false`: the cannot-prove error, never "no children" (Task 3 GREEN `partial-empty`).
3. More children than `mr_list`'s default limit of 50 (`full: false` with rows): the stack-parent edge, with the message ending `, and more` (Task 3 GREEN `github-stack-parent`).
4. A GitHub refusal at the daemon (`ForgeHttpError` 502): an error naming GitHub, never an empty list (Task 1, daemon test).
5. An MR whose `mr_view` gives a blank source branch: `mr_list` refuses the blank `targetBranch` before any daemon call, which takes the tool-error edge. Already pinned by `mr_list refuses a filter that is blank after trimming, before any daemon call` in `lib/mcp/__tests__/mr-read-tools.test.ts`; no new test.

- [ ] **Step 3: Add the prose bullet** under "What this graph cannot show", between "What is broken" and "A pipeline with no verdict", titled `**The stack-parent check.**`. It says, in the stage's voice:
  - `<source branch>` is the `sourceBranch` the stage's first `mr_view` read; the call passes no `limit` and no `state`, so it reads up to 50 open MRs (drafts included) by any author.
  - Only `full: true` with no MR listed goes on to the lease check and the rebase. A rebase would rewrite the commits every listed MR is built on.
  - Any MR listed, whatever `full` says: error `MR !<iid> is a stack parent (stacked on it: <children>); a rebase would strand the stack: needs a restack of the stack root`, where `<children>` is each listed MR as `!<iid>`, comma separated, followed by `, and more` when `full` is false.
  - A tool error, or no MR listed with `full: false`: error `cannot prove MR !<iid> has no stacked children: the live target-branch query failed (<reason>)`, where `<reason>` is the tool's error quoted as written, or `partial list, no rows`.
  - No retry and no escalation here: nothing has moved yet, so a human relaunch costs nothing. The check never reads rt's MR cache and never treats a failed read as "no children".
