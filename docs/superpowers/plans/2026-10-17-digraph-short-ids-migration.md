# Digraph Short Ids Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert every dot graph in the mattstack plugin to short ids, regenerate its generated copies, prove behavior on four more skills, then make plugin CI and certify require short ids while team packs keep both forms.

**Architecture:** The prototype branch already ships the checker rules, `convert.py` with slug maps and `--verify`, the rewritten process-digraphs rule, and two converted skills. This plan converts the rest cluster by cluster with the same scripted, verify-proven method. It regenerates the compiled shepherdr copy and `apps/board/skills`, runs sampled RED/GREEN on ship, receive-review, gate-protocol and shepherdr, then turns on `check-dot.py --short-ids` for plugin skill dirs.

**Tech Stack:** Python 3 (`check-dot.py`, `convert.py`), bash, Graphviz `dot`, `bun cli.ts skills compile|expand|check`, `claude -p` (tool-less), GitHub Actions (`checks.yml`).

**Spec:** `docs/superpowers/specs/2026-10-17-digraph-short-ids-design.md` (option A approved). Matt's answer on milestone gate 0cf47cb8 is binding: migrate all plugin graphs, then require short ids. It also sets the RED/GREEN sample of ship, receive-review, gate-protocol and shepherdr (tool-less recipe, 5 reps, deviations no higher than full-text), the docs to update, the next patch version above main's, and the PR flow.

## Global Constraints

- Write only under:
  - `plugins/mattstack/**`
  - `apps/board/skills/**` (regenerated by `skills:expand:board`, never hand-edited)
  - `.github/workflows/checks.yml` (the check-dot step only)
  - `docs/superpowers/specs/` and `docs/superpowers/plans/`
  - `.superpowers/`
- `apps/board/skills-src/**` is untouched. The board's own graphs keep sentence ids; a per-graph rule allows mixed forms across graphs in one file.
- Every `bun cli.ts` or `bun run skills:*` command runs under `env -i HOME=<scratch>/home PATH="$PATH"` with `--mattstack-dir <scratch>/ms` where the command takes one. Never against `~/.mattstack`. Never run a compiled rt binary.
- Conversion method, per file:
  1. `convert.py --emit-slugs` to a map under `plugins/mattstack/docs/superpowers/tests/2026-10-17-digraph-ids/slugs/<name>.json`.
  2. Hand-edit the map. Each slug names its step in 1 to 4 words after any required prefix. A plaintext id starts with its call's normalized first word. A STOP id starts with `stop_`. No digits, no near-twins.
  3. `convert.py --scheme all --slugs <map>` in place.
  4. Check it:
     - `convert.py --verify <base copy> --slugs <map>` is ok.
     - `render.sh` passes.
     - `check-dot.py` reports 0 findings.
     - `certify.sh <dir>` passes.
     - `git diff` touches only lines inside dot fences.
- The base for RED and for `--verify` copies is `3aad678d6`: main at the rebase, sentence ids everywhere outside this branch's two prototypes.
- The tool-less recipe is exactly `claude --model sonnet --tools "" --strict-mcp-config --setting-sources local --settings '{"disableAllHooks":true}' --disable-slash-commands --no-session-persistence`. Run it through `run-reps.sh` (prompt as `-p -- "$(cat f)"`), one fresh empty dir per rep, 5 reps per scenario per side. Rep outputs stay in the scratchpad.
- RED/GREEN pass bar: GREEN deviations ≤ RED, per skill and per scenario. A miss gets a slug or rule fix and a GREEN rerun, at most 2 rounds, then the table goes in the report with the miss.
- No employer names or slugs, no ticket ids. `bun run purity` before any push.
- No em or en dashes in committed prose.
- One commit per task, message ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- The plugin version is bumped once, in Task 14, to the next patch above main's at that time (0.31.24 today). `minEngine` is unchanged: no tool changes.
