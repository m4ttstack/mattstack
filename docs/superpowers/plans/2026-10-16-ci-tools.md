# CI tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move CI triage, job listing, watch bookkeeping and lease guarding into rt's MCP server: `ci_triage`, `pipeline_jobs`, `ci_watch {attend: true}`, a lease keepalive, and a `leaseMrUrl` guard on `git_push` and `mr_retry`.

**Architecture:** A pure triage engine (`lib/ci/triage.ts`) runs over a `TriageForge` interface; a GitLab adapter (`lib/ci/gitlab-forge.ts`) implements it over existing daemon verbs, and a test fixture adapter implements it over the shell suite's scenario files. `ci_watch`'s loop (`lib/ci/watch.ts`) gains an attend mode driven by a persisted per-MR state file (`lib/ci/watch-state.ts`); lease claim, re-claim and keepalive live in `lib/ci/lease-guard.ts` and `lib/ci/lease-keepalive.ts`. Team patterns come from six `ci.triage.*` settings.

**Tech Stack:** Bun, TypeScript, `bun:test`, zod (settings schemas), rt daemon verbs via `rtCommand`.

**Spec:** `docs/superpowers/specs/2026-10-16-ci-tools-design.md`

## Review Focus

1. A pipeline whose `forge:get` page comes back `truncated` must be re-read smaller, never silently short; a still-truncated page is a tool error (Task 4 pins it).
2. Two `ci_watch {attend}` calls on the same MR from a session that crashed and a fresh session: the fresh session must stand down while the old lease is fresh and take over once stale, without inheriting a fresh budget (Task 8 pins it).
3. A watch-state file left from a different commit, or corrupt JSON, must not break the watch: corrupt reads as empty, an older commit carries only its last pipeline id forward (Task 6 pins it).
4. A job name with regex metacharacters (`test+coverage`) and a `noisy-jobs` entry with them must match literally (Task 3 pins it via the fixture case; Task 2 pins the noisy substring rule).
5. A keepalive entry whose heartbeat throws (busy lock) must survive to the next tick, and the timer must never keep a CLI process alive (`unref`) (Task 7 pins both).
