# Mod Kit and Mod Build Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A shared `@mattstack/mod-kit` package with JSX components and hook-side patterns, mods authored in `mods/<name>/`, and a build that bundles each mod into the committed `plugins/<name>/` folder Claude Code reads; gate-form moved onto it; a `/kit-gallery` catalog and a README.

**Architecture:** The kit keeps the spike's line model (spans and lines carrying click actions) under a JSX component layer. `scripts/mods/build.ts` bundles each mod's hooks entry and Client entries with `Bun.build`, inlining the kit, then validates the output with `claude plugin validate`. CI checks the committed output is fresh and runs each built mod's `claude plugin test`.

**Tech Stack:** TypeScript, Claude Code mod API 2.1.322 (`claude-code`, `claude-code/testing`), Bun 1.4.4 (`Bun.build`, `bun test`), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-12-mod-kit-design.md`

## Global Constraints

- Mods may import only their own files: everything shared is inlined at build time.
- Built hooks module: `register` is `export function register(on: On): void`, a top-level function declaration.
- A function that receives `$` is declared at the top of the same file (the bundle satisfies this by inlining).
- `atom({ plugin: '<name>', key: '...' } as const, ...)` refs are literals.
- No `import(` anywhere in built output.
- Modules never declare, import or take a parameter named `h` or `Fragment`, and carry no `@jsx` pragma (the engine owns both and prepends its own pragma).
- `Bun.build` settings from the probe: `format: 'esm'`, `target: 'browser'`, `splitting: false`, `minify: false`, `external: ['claude-code']`, the mod tsconfig's `jsx: "react"`, `jsxFactory: "h"`, `jsxFragmentFactory: "Fragment"`.
- CI's pinned CLI is `@anthropic-ai/claude-code@2.1.322`; the committed types snapshot comes from that version.
- Dark terminals only; colours are the spike's (`theme.ts` at spike commit `2f04ad07f`).
- Every folder under `plugins/` has a `plugin-<name>` job in `.github/workflows/checks.yml`, listed in the `checks` job's `needs` and its result check.
- gate-form stays out of `marketplace/marketplace.json`.
- `$.state` refs are spelled with literals in the module that uses them: a mod declares its atoms; kit helpers take atoms (`Atom<T>` from `claude-code`), never `{ plugin, key }` refs.
- A `Client`'s `module` is a string literal on the element: the kit's hideable pane writes `module="./band.tsx"` itself, and a mod using it lists `band.tsx` in `mod.json` `clients`.
- Test layout: bun tests `*.test.ts(x)` under `src/` (run by `bun run mods:test`, which runs only `./packages/mod-kit/src` and `./mods/*/src` and preloads `packages/mod-kit/test/jsx-preload.ts` to stand in for `h`/`Fragment`); harness tests in `mods/<name>/harness/*.test.tsx`, copied into the built `hooks/` and run only by `claude plugin test`.
- A change under `plugins/<name>/` needs a version bump (`scripts/ci/plugin-version-bumped.ts`): bump `mod.json` `plugin.version` of every mod whose output a change rebuilds, kit edits included.
- Behaviour parity reference: `plugins/gate-form/` at `2f04ad07f` plus the live copy (identical except `register` already a function declaration).

## Review Focus

- **Stale built output:** a source edit committed without `mods:build` must fail CI's freshness step, not ship. Task 9 adds a test that a dirty build diff fails.
- **Several Client modules in one mod:** every `module="./x.tsx"` literal in the hooks entry must be rewritten to its built name, and a `module` naming a file not listed in `mod.json` must fail the build. Task 3 tests both.
- **Narrow panes (30 columns):** tab strip, button row and brand bar with Hide must not throw or produce lines wider than the width. Task 2 tests each at width 30.
- **Unfocused drawing of every fill:** each `FILL` tone and `BRAND` colour must have an unfocused shade that is not lighter than its rest shade. Task 2 tests it across all tones by relative luminance.
- **Pointer and focus edge cases:** dragging off a pressed button and releasing does nothing; the first click on an unfocused surface only focuses; the focus stand-in clears on `prompt.edit`, `prompt.submit` and `ui.focus`. Task 5's harness tests drive each.
