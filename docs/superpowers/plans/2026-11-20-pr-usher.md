# pr-usher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans (Native, or its Native with reviews variant) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a `mattstack:pr-usher` skill (an always-on agent that reviews, settles and merges ready PRs in its repo) and a shipped rule that tells every agent to hand ready PRs to a live usher.

**Architecture:** Plugin text only, no rt code. Presence is rt chat: the usher signs in with status `pr-usher` and joins `#pr-usher`; authors find it in `rt chat who --json` and DM a handoff. The usher's loop uses existing MCP tools (`mr_list`, `mr_threads`, `ci_watch`, `mr_merge`) and self-paced wakeups.

**Tech Stack:** mattstack plugin markdown (standard, non-compiled skill), rt chat CLI, mattstack MCP tools, `bun test`.

**Spec:** `docs/superpowers/specs/2026-11-20-pr-usher-design.md`

## Global Constraints

- Before writing any skill text, load `superpowers:writing-skills` and `mattstack:editing-skills`; the usher's loop also follows `mattstack:process-digraphs`.
- Shipped rule: plain markdown, a `#` title, no frontmatter, no person's name or path (guarded by `lib/claude-rules/__tests__/no-personal-names-in-shipped-rules.test.ts`).
- Any change under `plugins/mattstack/` bumps `plugins/mattstack/.claude-plugin/plugin.json` version (currently `0.32.86`; re-check main right before merge).
- No em or en dashes in shipped text.
- Presence status string is exactly `pr-usher`; room is exactly `pr-usher`.
- The usher merges without asking; this exception is scoped to the usher only.

## Review Focus

1. Two ushers started in the same repo: the second must see the first (online, status `pr-usher`, same repo) and exit, not double-review.
2. A PR flips back to draft, or gets new commits after review: the usher drops it (draft) or re-checks threads and CI on the new head before merging.
3. Author goes offline mid-review: usher takes over fixes in its own worktree; author returns: usher hands back.
4. CodeRabbit never posts (not installed, rate limited, or silent past the wait): usher falls back to an Opus subagent review, never merges unreviewed.
5. Merge queue drop (`mr_merge` returns dropped): usher reads why, routes the fix, requeues with `requeue: true` once fixed.

Each line is a RED/GREEN pressure scenario in Task 2.

### Task 2: The pr-usher skill

**Files:**
- Create: `plugins/mattstack/skills/pr-usher/SKILL.md`

**Interfaces:**
- Consumes: handoff DM line from Task 1.
- Produces: skill `name: pr-usher`; posts `pr-usher on duty for <repo>` / `pr-usher off duty for <repo>` to the repo room, and `merged <PR> (<title>)` to `#pr-usher`.

- [ ] **Step 1:** Load `mattstack:editing-skills` and `mattstack:process-digraphs`. RED baseline: run the five Review Focus scenarios plus "start as usher, one ready PR, CodeRabbit approves, CI green" against a subagent given only the spec. Record failures verbatim.
- [ ] **Step 2:** Write `SKILL.md`. Frontmatter description starts "Use when" and triggers on: being the PR usher, watching a repo's PRs and keeping them moving, "pr-usher". Body sections:
  - Start: sign in with `--status pr-usher`, join `pr-usher`, refuse if another online usher for this repo exists, announce in the repo room.
  - The loop as a digraph (per process-digraphs): tick, list ready non-draft PRs (`mr_list`), per-PR walk `needs review -> awaiting review -> findings relayed -> threads settled -> CI green -> merging -> merged`, then a `ScheduleWakeup` (idle cadence 1200s; 300s while any PR is mid-flight). Chat DMs wake it sooner.
  - Review: wait for CodeRabbit up to 15 minutes after ready; on rate limit, absence or timeout, dispatch an Opus subagent (effort `high`) review and post its findings as PR comments.
  - Owner: from the handoff DM, else head-branch match in `rt chat who --json`. Questions and findings go to the owner by `rt chat dm`. Owner offline: fix in the usher's own worktree (`rt:worktree`), push, resolve threads; owner back online: hand back.
  - Settled means every review thread resolved or answered with a reason, on the current head.
  - Merge: `mr_merge` with `wait: true`; on a dropped result read why, route the fix, then `requeue: true`. Re-verify head, threads and CI immediately before merging. Merging needs no human confirmation for this agent; post each merge to `#pr-usher`.
  - Stop: on sign-off, post off duty and sign out.
- [ ] **Step 3:** GREEN: rerun all Step 1 scenarios with the skill loaded; every one must take the expected path. Close loopholes found and rerun.
- [ ] **Step 4:** Commit `add pr-usher skill`.
